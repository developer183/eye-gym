# 目力練功房

給**戴著矯正眼鏡**、需要做近距離精細目力練習的孩子用的每日練習 app。
純靜態網頁，**完全離線可用**，沒有後端、沒有帳號、沒有任何對外連線。

**線上版：https://graylightai.github.io/eye-gym/**

手機開啟後「分享 → 加入主畫面」，就是全螢幕、鎖直板的 app。

> **這不是醫療器材，也不能治療疾病。** 它做的是把練習時間記下來、自動調整難度，
> 並整理成回診時可以給醫師看的紀錄。遮眼側別與每日時間一律以眼科醫師的指示為準。

## 它跟一般小遊戲合集的差別

### 一、每天只有一件事

打開就是「今天」：進度環、遮哪隻眼、視標多大、一顆開始按鈕。
按下去之後 app 自己排關卡、自己計時、到了時間自己收工，中間自動插休息。
家長不用決定玩哪一關、玩多久。

### 二、視標大小自動找

視標大小是這個 app 唯一真正重要的變數，但家長無從判斷該設哪一級。
所以改成 app 自己找：

- 只看**小缺口**（校準過的蘭氏環）和**找一樣的**（細節辨別）這兩關的表現——
  它們才代表解析力。迷宮、數字接龍、三個一組練的是搜尋與追蹤，答錯不代表看不清楚
- 同一級做滿 12 題、正確率 ≥85%、反應時間中位數 ≤4.5 秒 → **縮小一級**
- 做滿 8 題但正確率 <60% → **退回一級**
- 「**穩定視標**」＝ 同一個大小做滿 10 題且正確率站上 80% 的最細一級

家長隨時可以關掉自動、自己設。

### 三、回診時給得出數字

「進度」頁有一張可以直接截圖給醫師的卡片：醫囑、有練習的天數、達標天數、
累積時間、目前穩定視標與換算視力、對比設定，以及一段說明這些數字怎麼來的註腳。

另外有 30 天的視標大小趨勢圖——**趨勢比單次分數有用**。

卡片下面還有「**複製成文字**」與「**分享**」：診間裡用講的或貼訊息比遞手機方便，
截圖還會因為卡片太長而被切掉。複製出來是一段可以直接唸的純文字，
最後附上數字怎麼來的說明與「這不是視力檢查」的提醒。

## 五個關卡

| 關卡 | 練什麼 |
|---|---|
| 小缺口 | 蘭氏環（國際標準視標，外徑 D、筆畫與缺口各 D/5），解析力 |
| 找一樣的 | 視覺辨別。三種題型輪流：找一樣、找不同、找成對，有連擊 |
| 三個一組 | 指定目標搜尋 + 圖形背景辨別。129 個圖案層層堆疊，像素級點擊判定 |
| 走迷宮 | 視覺追蹤 + 眼手協調 |
| 數字接龍 | 視覺搜尋、掃視（舒爾特方格） |

## 視標大小怎麼算

視標以**毫米**定義（14 / 10 / 7 / 5 / 3.5 / 2.5 mm），不是用 px——px 在不同手機上
實際大小差很多。設定裡可以拿一張健保卡／悠遊卡校準，校準後毫米數才準。

換算成 30 公分處的視角：缺口角度（分角）＝ (D/5) ÷ 300 × 3437.75，視力 ＝ 1 ÷ 角度。
手機能顯示的最小視標大約落在視力 0.2 上下，再小螢幕就畫不出缺口了。
**這個範圍對訓練夠用，但它不是視力檢查。**

## 換手機不會掉紀錄

紀錄只存在這台手機裡（沒有帳號、沒有雲端，也就不會外流）。所以設定裡有一組
**匯出備份／讀回備份**：匯出是一個 `.json` 檔，用 AirDrop、LINE、郵件傳到新手機，
再從設定裡讀回去，所有孩子的醫囑、難度、校準與全部紀錄都會回來。
讀回去之前會先問一次，而且只吃這個 app 匯出的檔案，選錯檔會被擋下來。

建議**每次回診前匯出一份**存起來。

## 多個孩子

每個孩子的醫囑、難度、校準與全部紀錄都分開存。上方名字可以切換。

## 檔案

```
index.html      畫面骨架（樣式與程式拆在 css/ 與 js/，見「一起開發」）
css/            3 個樣式檔
js/             11 個程式檔，一檔一責任
```

> 改過 `index.html` 或 `img/` 之後**一定要跑 `python3 build-sw.py` 再 commit**，
> 否則已經裝在主畫面的 app 會一直吃舊快取。

本機測試要起伺服器（`file://` 下 Service Worker 不會註冊）：`python3 -m http.server 8000`

## 一起開發

程式碼已經拆成一檔一責任，兩個人同時改不同檔案不會衝突。

```
index.html          畫面骨架
css/tokens.css      顏色、字體、陰影 ← 想換配色只改這裡
css/app.css         版面與元件
css/games.css       五個關卡的樣式
js/util.js          小工具
js/content.js       文案、視標級距、難度門檻 ← 不碰程式邏輯也能調
js/state.js         孩子資料與設定的讀寫
js/engine.js        自適應難度與每日紀錄
js/draw.js          繪圖：蘭氏環、小生物、迷宮、貼圖、花樣背景
js/games.js         關卡登記表
js/game-*.js        五個關卡，一關一個檔
js/ui.js            畫面流程
```

`<script>` 依序載入，沒有打包步驟——改完存檔、瀏覽器重新整理就看得到。

### 協作模型：兩個人都走 PR

`main` 就是 GitHub Pages 服務的分支，也就是小孩手機上那個 app。所以 `main` 加了 ruleset：
**必經 PR、禁止刪除、禁止 force push，沒有任何 bypass**。任何人（包括 repo owner）
都不能直接推 `main`，線上版永遠有一次 diff 把關。

```
她：開發 → 改 → 送出給 Jessie 檢查   （開分支、rebase、push、開 PR）
我：檢查 → 看 diff／本機跑一遍 → 合併  （合併的那一刻才上線）
我自己改：上線                         （同樣開 PR，可選擇立刻合併）
```

PR 的必要核准數設成 0——GitHub 不讓作者核准自己的 PR，設成 1 會連我自己的修改
也卡住。所以「她不能自己合併」這一層是流程上的（她的按鈕不會帶她到那個頁面），
不是技術上的。要硬性擋住就得改成 fork + PR，代價是她要多管一個 remote。

### 點兩下就能用的檔案

| 檔案 | 誰用 | 做什麼 |
|---|---|---|
| `設定這台電腦.command` | 她 | 新電腦第一次：檢查 git／python／gh、帶著登入、設 noreply 署名、裝 QR 工具 |
| `開發.command` | 兩人 | 先 `git pull --ff-only`，再起本機網站（綁區網）並印出 QR code |
| `送出給 Jessie 檢查.command` | 她 | build-sw → 開 `edit-<時間>` 分支 → rebase → push → 開 PR |
| `檢查.command` | 我 | 列 PR、看 diff、`gh pr checkout` 在本機跑、合併或退回留言 |
| `上線.command` | 我 | 同上但走 `j-<時間>` 分支，開完 PR 可以直接合併 |
| `還原.command` | 兩人 | 丟掉未送出的修改並回到 `origin/main` |

腳本全部用 `cd "$(dirname "$0")"`，沒有寫死路徑，clone 到任何位置都能跑。

### 新電腦怎麼開始

不用傳任何檔案給她——**所有 `.command` 都住在 repo 裡，她還沒 clone 就一顆按鈕都沒有**。
所以 bootstrap 交給她 Mac 上的 Claude Code：請它 clone 到桌面，然後點 `設定這台電腦.command`。

曾經寫過一個單獨 AirDrop 給她的 `安裝到新電腦.command`，已經刪掉，因為它反而是唯一會
踩到 Gatekeeper 的東西：

> **`git clone` 下來的檔案不帶 `com.apple.quarantine`**（已實測 `xattr` 為空），
> 所以 clone 下來的 `.command` 點兩下直接開。隔離標記是下載的那個 app 加上去的
> （瀏覽器、AirDrop、郵件），git 不會加。

換句話說，用 AirDrop 傳安裝檔是**自己製造**出一道「無法打開，因為來自未識別的開發者」，
而讓 Claude Code 去 clone 則完全繞過這件事。

### 手機預覽

`開發.command` 綁 `0.0.0.0` 並用 segno 在終端機印 QR code（自己算半格字元並強制
黑字白底，因為 segno 的 `compact` 模式假設深底終端機，macOS 預設白底會讓極性反過來）。

那兩項要在正式網址上測。

`給太太的說明.html` 是寫給完全沒寫過程式的人的入門文件。

### 新增一個關卡

在 `js/game-你的名字.js` 寫：

```js
GAMES.yourid = {
  name: '關卡名稱',
  desc: '一句話說明',
  rounds: 10,                       // 一輪幾題
  thumb: () => '<svg…>',            // 選單上的小圖
  render(field, api) {
    // 把題目畫進 field
    // 答對 api.pass()、答錯 api.miss()、要改題數 api.setTotal(n)
  },
  cleanup() {}                      // 選用：移除事件監聽
};
```

然後在 `index.html` 加一行 `<script src="js/game-你的名字.js"></script>`——就這樣。
關卡順序是從 `GAMES` 自動讀的（順序＝`<script>` 的載入順序），不用再去別的地方登記。

**某一關的程式寫壞了也不會把 app 弄死**：出問題的那一關會顯示「這一關出了問題」
加上錯誤訊息，按「跳過這一關」就接到下一關，當天的練習照樣做完。
選單上的小圖畫不出來也只是變成 🎯。所以放心改，改壞了看得到原因。
